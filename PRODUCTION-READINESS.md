## B. Changes implemented

- Production validates MongoDB configuration, JWT secret, canonical HTTPS origin, port, absolute upload path, explicit proxy policy, required build/assets, database connectivity, and indexes before listening on `0.0.0.0`. Development retains loopback binding and its existing defaults. Production does not fall back to sample products or blog posts.
- `/api/health` returns 200 only when ready with a successful database ping; otherwise 503. Probes have a 1,500 ms deadline, share concurrent work, and expose no connection strings.
- Admin uploads and runtime wholesale imports share `UPLOAD_DIR`. Existing `/uploads/<filename>` references remain valid. Sharp validates and re-encodes images. Writes do not overwrite existing files; serving rejects unsafe paths and symlinks, returns missing-image 404s, and handles storage errors safely. The upload filesystem must support same-directory hard links.
- Express `trust proxy` stays false. Direct production mode rejects forwarding headers. The optional trusted mode requires explicitly verified socket peers and a single valid `X-Real-IP`; spoofed forwarding lists do not select the limiter identity. No Railway trust addresses were invented or enabled.
- SIGTERM/SIGINT mark readiness false, stop new connections, drain active HTTP responses, then disconnect MongoDB. Shutdown is idempotent and bounded by 25 seconds.
- Supported Node range is `>=22.12.0 <23`; build dependencies must be installed before Vite builds. Documentation covers Linux Sharp installation, persistent storage, migration, backups, and rollback. Secret, backup, upload, and artifact exclusions were expanded. No unrelated dependencies were installed or upgraded.
- Existing retail, admin, finance, udhari, and wholesale flows remain covered. Wholesale enquiries remain enquiries and are not automatically recorded as sales.
